# SPEC — Веб-приложение «Библиотека: бронирование книг»

Версия: 1.1 (вариант «Библиотека»)
Дата: 15.11.2026; 16.11.2026 — база данных переведена с MySQL 8 на SQLite
(файл `backend/db.sqlite3`).

## 1. Цель проекта

Веб-приложение библиотеки: читатель ищет книгу в каталоге, бронирует свободный
экземпляр на нужные даты или встаёт в очередь, если свободных нет. Библиотекарь
выдаёт и принимает книги, работает с очередью. Администратор управляет
пользователями, фондом и смотрит отчёты.

Особое правило варианта: **если свободных экземпляров нет, читатель встаёт в
очередь, а при возврате книга резервируется за первым в очереди.**

Проект выполняется по дисциплине «AI Driven Development»: код пишется с помощью
AI-агента (OpenCode), все сессии сохраняются в `prompts/`, ход работы — в
`docs/AI_LOG.md`.

## 2. Стек

| Слой | Технология |
|------|------------|
| Frontend | React 18 + Vite, react-router-dom, axios |
| Backend | Python 3.12, Django 5.x, Django REST Framework |
| БД | SQLite 3 (файл `backend/db.sqlite3`, кодировка UTF-8) |
| Авторизация | JWT: access (15 мин) + refresh (7 дней), SimpleJWT + blacklist |
| AI-агент | OpenCode |
| Документация | Markdown в `docs/` |

## 3. Роли

- **Читатель (reader)** — регистрируется сам, ищет книги, бронирует экземпляры,
  встаёт в очередь, смотрит и отменяет свои брони.
- **Библиотекарь (librarian)** — создаётся администратором: выдаёт и принимает
  книги, снимает брони, видит очередь по книге.
- **Администратор (admin)** — пользователи, фонд (книги и экземпляры), все брони,
  очередь, отчёты, журнал действий.

Роль хранится в `users.role` и проверяется **только на backend**. Frontend лишь
скрывает недоступные разделы.

## 4. Функциональные требования

### 4.1 Аутентификация
1. Регистрация читателя: email, пароль, ФИО, телефон. Роль всегда `reader`.
2. Вход по email и паролю → `access` + `refresh` и данные пользователя.
3. Access передаётся в `Authorization: Bearer <token>`.
4. При истечении access frontend автоматически вызывает `/api/auth/refresh`
   и повторяет исходный запрос один раз.
5. Недействительный refresh → принудительный выход.
6. Выход: refresh попадает в blacklist, повторный `/refresh` отдаёт 401.
7. Пароли — только в виде хеша.

### 4.2 Каталог книг
- Список книг: обложка, название, автор, жанр, год, краткое описание,
  количество экземпляров и сколько свободно.
- Поиск по названию и автору, фильтр по жанру, **пагинация на стороне сервера**
  (DRF `PageNumberPagination`, 9 книг на страницу).
- Карточка книги с обложкой (`cover_url`), описанием и списком экземпляров.
- CRUD книг и экземпляров — только администратор.
- Неактивные книги и списанные экземпляры не участвуют в выдаче.

### 4.3 Свободные экземпляры
`GET /api/books/{id}/availability?start_date=&due_date=` возвращает свободные
экземпляры на интервал.

Экземпляр считается занятым, если выполняется любое условие:
- есть бронь/выдача со статусом `created` или `active`, пересекающаяся по датам;
- есть действующее удержание (`ready`) другого читателя, срок которого не истёк.

Пересечение: `start_date < new_due AND due_date > new_start`.
Смежные интервалы (до 1 июля / с 1 июля) не конфликтуют.

### 4.4 Бронирование (выдача)
- Читатель выбирает книгу, даты и (опционально) конкретный экземпляр.
- `due_date` по умолчанию = `start_date + 14 дней`, максимум 30 дней, не в прошлом.
- Создание — в транзакции, которая берёт блокировку записи до чтения
  (`BEGIN IMMEDIATE`): сначала блокировка, затем проверка пересечения, затем
  `INSERT`. Так проверка и вставка не расходятся между потоками.
- Конфликт → `409` с кодом `copy_taken`.
- Если свободных экземпляров нет → `409` с кодом `no_copies` и подсказкой встать
  в очередь.
- Индекс: `loans(copy_id, start_date, due_date)`.

### 4.5 Статусы брони/выдачи

```
created   -> active, cancelled
active    -> returned
returned  -> (конечный)
cancelled -> (конечный)
```

- `created` — бронь создана, книга ещё не выдана.
- `active` — библиотекарь выдал книгу.
- `returned` — книга принята.
- `cancelled` — бронь отменена читателем или библиотекарем.
- Клиент может отменить только свою бронь в статусе `created`.
- Библиотекарь/админ меняют статус по матрице; недопустимый переход → `409`.
- Матрица описана в одном месте: `loans/statuses.py`.
- Смена статуса + `LoanStatusHistory` + `ActivityLog` — в одной транзакции.

### 4.6 Очередь (особое правило)
- Если на нужные даты нет свободного экземпляра, читатель может встать в очередь
  на **книгу** (не на экземпляр): `POST /api/reservations`.
- Очередь FIFO: `ORDER BY created_at, id`. Один читатель — одна активная заявка
  на книгу (повторная → `409 already_queued`).
- Позиция в очереди возвращается в API (`position`).
- **При возврате книги** библиотекарь ставит `returned`. В той же транзакции
  освободившийся экземпляр резервируется за первым в очереди:
  `reservation.status = ready`, `hold_until = now + 48 часов`.
- Пока удержание действует, экземпляр недоступен другим.
- Читатель с удержанием создаёт бронь на этот экземпляр; после этого заявка
  становится `fulfilled`, а удержание снимается.
- Если `hold_until` истекло, удержание считается недействительным **без фоновой
  задачи**: при проверке доступности и при следующем возврате оно пропускается,
  заявка получает `expired`, а экземпляр уходит следующему в очереди.
- Читатель может отменить заявку: `DELETE /api/reservations/{id}` → `cancelled`.
- Изменения очереди — в транзакции с блокировкой записи (`BEGIN IMMEDIATE`),
  чтобы двое не получили одно удержание.

### 4.7 Кабинет читателя
- Текущие брони, история, отмена.
- Мои заявки в очереди с позицией и статусом.
- Уведомление в интерфейсе, если есть удержание и его срок.

### 4.8 Панель библиотекаря
- Выдачи на сегодня и предстоящие, фильтры по статусу и дате.
- Действия: выдать (`created → active`), принять (`active → returned`),
  отменить бронь.
- Очередь по книге: кто первый, у кого удержание, до какого времени.

### 4.9 Административная панель
- Пользователи: список, поиск, создание библиотекаря, смена роли, блокировка.
- Книги: CRUD, обложка по URL, включение/выключение.
- Экземпляры: добавление, инвентарный номер, состояние, списание.
- Все брони и заявки с фильтрами.

### 4.10 Отчёты и CSV
- За период: количество выдач, возвратов, отмен, книг в очереди, топ-5 книг,
  загрузка экземпляров.
- Считается **SQL-агрегацией** (`annotate`/`Count`/`Sum`), без циклов по всем
  записям в Python.
- Период ставится в условие `ON` у `LEFT JOIN`, чтобы книги без выдач не исчезали.
- Только параметризованные запросы — без склейки SQL строками.
- Экспорт CSV (UTF-8 с BOM): `loans.csv`, `books.csv`.

### 4.11 Журнал действий
- Таблица `activity_log`: кто, что сделал, над каким объектом, когда, IP.
- Логируются: регистрация, вход/выход, создание и отмена брони, смена статуса,
  выдача и возврат, постановка в очередь и удержание, изменения фонда.
- Просмотр — только администратор.

### 4.12 Состояния интерфейса
На каждом экране: **загрузка**, **пустой список** с подсказкой, **ошибка** с
кнопкой «Повторить». Конфликт показывается текстом: «На эти даты свободных
экземпляров нет. Встать в очередь?»

## 5. Модель данных (7 таблиц)

| # | Таблица | Назначение |
|---|---------|------------|
| 1 | `users` | пользователи и роли (`reader`/`librarian`/`admin`) |
| 2 | `books` | каталог книг |
| 3 | `book_copies` | физические экземпляры книги |
| 4 | `loans` | брони и выдачи |
| 5 | `loan_status_history` | история смены статусов |
| 6 | `reservations` | очередь читателей на книгу |
| 7 | `activity_log` | журнал действий |
| 8 | `token_blacklist_*` | отозванные refresh-токены (SimpleJWT) |

### Ключевые поля

**users**: `id`, `email` (unique, логин), `password`, `full_name`, `phone`,
`role`, `is_active`, `created_at`

**books**: `id`, `title`, `author`, `genre`, `year`, `description`, `cover_url`,
`is_active`, `created_at`

**book_copies**: `id`, `book_id` FK → books, `inventory_number` (unique),
`condition` (`new`/`good`/`worn`), `is_active`

**loans**: `id`, `reader_id` FK → users, `copy_id` FK → book_copies,
`start_date` DATE, `due_date` DATE, `status`, `comment`, `created_at`, `updated_at`
Индекс: `(copy_id, start_date, due_date)`, `(reader_id)`.

**loan_status_history**: `id`, `loan_id`, `old_status`, `new_status`,
`changed_by_id`, `created_at`

**reservations**: `id`, `book_id` FK → books, `reader_id` FK → users,
`status` (`waiting`/`ready`/`fulfilled`/`cancelled`/`expired`),
`hold_copy_id` FK → book_copies (nullable), `hold_until` DATETIME (nullable),
`created_at`, `updated_at`
Индекс: `(book_id, status, created_at)`.

**activity_log**: `id`, `user_id` (nullable), `action`, `entity_type`,
`entity_id`, `description`, `ip_address`, `created_at`

### Каталог

### Брони и очередь
| Метод | Путь | Доступ |
|-------|------|--------|
| GET | `/api/loans` | reader (свои), librarian (все), admin |

| PATCH | `/api/loans/{id}/status` | reader (только cancel), librarian, admin |

| POST | `/api/reservations` | reader |

### Админ и отчёты
| Метод | Путь | Доступ |
|-------|------|--------|
| GET/POST/PATCH | `/api/users`, `/api/users/{id}` | admin |
| GET | `/api/logs` | admin |
| GET | `/api/reports/summary?date_from&date_to` | admin |
| GET | `/api/reports/loans.csv?date_from&date_to` | admin |
| GET | `/api/reports/books.csv` | admin |

Ошибки единообразно:
```json
{ "detail": "На эти даты экземпляров нет", "code": "no_copies" }
```
Коды: 400 валидация, 401 токен, 403 роль, 404 нет объекта, 409 конфликт
(`copy_taken`, `no_copies`, `already_queued`, `bad_transition`).

## 9. Тесты (минимум 15, план — 23)

**Auth (7):**
1. Регистрация создаёт читателя.
2. Дубль email → 400.
3. Вход возвращает пару токенов.
4. Неверный пароль → 401.
5. Refresh выдаёт новый access.
6. Logout отзывает refresh → повторный refresh 401.
7. `/me` возвращает пользователя.

**Брони и права (9):**
8. Создание брони → 201, `due_date` рассчитан backend.
9. Пересечение по экземпляру → 409 `copy_taken`.
10. Смежные интервалы → 201.
11. Отменённая бронь не блокирует экземпляр.
12. 10 параллельных запросов на один экземпляр → 1×201, 9×409, одна запись
    (на SQLite потоки сериализует `BEGIN IMMEDIATE`; тестовая база — файл).
13. Читатель видит только свои брони.
14. Чужая бронь по прямому URL → 404.
15. Библиотекарь видит все брони, читатель не может менять чужой статус → 403.
16. Недопустимый переход статуса → 409.

**Очередь (4):**
17. Нет свободных экземпляров → 409 `no_copies`.
18. Постановка в очередь даёт корректную позицию; повторная → 409.
19. Возврат книги создаёт удержание у первого в очереди (`ready`, +48 ч).
20. Истёкшее удержание пропускается и уходит следующему (`expired`).

**Каталог, отчёты, журнал (3):**
21. Только админ управляет книгами; неактивная книга скрыта.
22. Отчёт считает выдачи и отмены корректно; CSV с BOM.
23. Создание брони и возврат пишутся в журнал действий.

## 11. Ограничения

- Одна библиотека, часовой пояс Europe/Moscow, без оплат и штрафов.
- SQLite: данные — файл `backend/db.sqlite3` внутри проекта, отдельный сервер БД
  не нужен. Плата за это: одна запись в момент времени и отсутствие блокировок
  строк (`select_for_update` на SQLite эффекта не даёт). Защиту от двойной
  выдачи обеспечивает `transaction_mode="IMMEDIATE"` — транзакция берёт
  блокировку записи до чтения.
- Тестовая база — файл `backend/test_db.sqlite3` (`TEST.NAME`): на in-memory
  базе с shared cache потоки падают с `database table is locked`.
- Период брони — по датам (целые дни), без выбора часов.
- Уведомления не отправляются: только запись в журнал и статус в интерфейсе.
- Загрузка файлов не используется: обложка — внешний URL.
- Учебный проект: без Docker и CI.
