## Ошибки агента

Записываются по мере появления: что сделал неверно, как обнаружено, как исправлено.

1. **MySQL не запускался как служба.** Обнаружено при первом `migrate`: подключение
   отклонено. Исправлено инициализацией data-каталога и ручным запуском `mysqld`.
2. **Таблица пользователя называлась `users_user`.** Обнаружено проверкой `SHOW TABLES`;
   добавлен `db_table = "users"` и миграция.
3. **Шаблон Vite поставил React 19 вместо React 18.** Обнаружено сверкой
   `package.json` со SPEC; зависимости зафиксированы на 18.3.1.
4. **Код ошибки `target_required` пропадал.** `ValidationError` из `validate()`
   сериализатора DRF раскладывается по полям, и вьюха возвращала `validation_error`.
   Обнаружено тестом `test_target_is_required`; проверка перенесена во вьюху.
5. **`405` из-за двух маршрутов с одним путём.** При добавлении API броней список
   и создание висели на одном `loans/` двумя разными вьюхами. Обнаружено живым
   запросом. Исправлено объединением в `LoanCollectionView` (GET/POST) и
   `ReservationCollectionView`.
6. **Сообщение об успехе пропадало после брони.** Панель брони размонтировалась
   при `availabilityLoading`, вместе с ней терялся `message`. Обнаружено e2e.
   Исправлено: панель рендерится, пока есть `availability`, а страница не
   размонтируется при фоновом обновлении.
7. **`const` в повторных `Runtime.evaluate`.** В e2e объявление `const card`
   сохранялось в глобальном контексте, второй вызов падал с `Identifier 'card'
   has already been declared`. Исправлено оборачиванием в IIFE.
8. **Неверная проверка даты в e2e.** Шаблон `/.+\d{2}\.\d{2}\.\d{4}/` требовал
   символ перед датой и не совпадал с «17.11.2026, 23:46». Исправлено на
   `/\d{2}\.\d{2}\.\d{4}/`.
9. **DOM-узел в `Runtime.evaluate` не сериализуется.** E2E возвращал
   `document.querySelector(...)` с `returnByValue` и получал пустое значение,
   затем таймаут. Обнаружено зависанием проверки вкладки. Исправлено:
   возвращать `Boolean(...)` или текст, а не сам узел.
10. **`runserver --noreload` не подхватил новые маршруты.** После добавления
    `/api/admin/users/` сервер продолжал отдавать HTML 404. Обнаружено живым
    запросом. Исправлено: перезапускать backend после изменения `urls.py`.
11. **`created_at__date` на MySQL зависит от таблиц таймзон.** Фильтр журнала по
    дате возвращал 0 записей, потому что `CONVERT_TZ` не знал `Europe/Moscow`.
    Обнаружено тестом `test_filter_by_date_range`. Исправлено сравнением с
    aware `datetime` (начало дня и начало следующего дня).
12. **Тест падал с `EOFError` на существующей `test_library_db`.** После
    прерванного прогона БД осталась, а `manage.py test` спрашивал подтверждение.
    Исправлено запуском с `--noinput` (и удалением старой тестовой БД).
13. **Публичные auth-эндпоинты разбирали старый `Authorization`.** Вход,
    регистрация и refresh отвечали `401`, если в браузере лежал просроченный
    access. Обнаружено аудитом и тестом. Исправлено `authentication_classes = []`
    у `RegisterView`, `LoginView`, `RefreshView`.
14. **Удержание простаивало после брони на другой экземпляр.** Читатель с заявкой
    `ready` брал другой экземпляр той же книги: заявка закрывалась, а удержанный
    экземпляр ждал 48 часов. Обнаружено разбором `fulfill_reservation`.
    Исправлено передачей `copy` и вызовом `assign_hold_to_next`.
15. **CRUD фонда не писался в журнал.** SPEC 4.11 требует журналировать изменения
    фонда, а создание, правка и удаление книг и экземпляров не оставляли записи.
    Обнаружено сверкой SPEC с `catalog/views.py`. Исправлено действиями
    `book_*`/`copy_*`, миграцией `users.0006` и тестами.
16. **CSV-выгрузка не экранировала формулы.** Название книги вида
    `=HYPERLINK(...)` выполнилось бы при открытии в Excel. Обнаружено аудитом
    `reports/services.py`. Исправлено `safe_csv_cell` и тестом.
17. **Поле пользователя называлось `date_joined`, а в SPEC — `created_at`.**
    Обнаружено сверкой модели со SPEC 5. Исправлено переименованием, миграцией
    `users.0007`, обновлением админки, сериализатора и раздела пользователей.
18. **Полный прогон тестов выглядел зависшим.** Вывод заворачивался в
    `Select-Object -Last`, пайп буферизовал результат, команда завершалась с
    `4294967295` без строк. Исправлено запуском `manage.py test` напрямую или с
    перенаправлением в файл; правило добавлено в `AGENTS.md`.
19. **Тест 10 потоков на SQLite падал с `database table is locked`.** Первый
    вариант настроек оставлял тестовую базу in-memory (`file:memorydb_default?
    mode=memory&cache=shared`): shared cache не держит блокировки между потоками.
    Обнаружено первым прогоном `loans.tests.test_concurrency`. Исправлено
    файловой тестовой базой (`TEST.NAME`) и `transaction_mode="IMMEDIATE"`;
    правило добавлено в `AGENTS.md` (разделы 3.1, 4, 7).
